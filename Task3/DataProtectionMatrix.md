# Матрица защиты данных (At Rest / In Transit)

| Данные | В чём необходимость защиты | Инструменты защиты |
|---|---|---|
| PII пациента (ФИО, ДР, контакты) | Риск утечек ПДн, соответствие закону; доступ строго по ролям/атрибутам | Encrypt-at-Rest (KMS/Vault), TLS/mTLS, RBAC/ABAC, маскирование UI, DLP экспорта |
| HEALTH (медзаключения, результаты анализов) | Спецкатегория; конфиденциальность и аудит доступа | Шифрование объектов (Secure Storage+KMS), версии+аудит, псевдонимизация/обезличивание для аналитики, mTLS к интеграциям |
| Финансы (чеки, проводки, договоры) | Предотвратить мошенничество/подмену, соответствие регуляторам | Подпись/хэш целостности, Encrypt-at-Rest, RBAC раздельно для кассы/буха, защищённые каналы к 1С |
| Журналы/операционные списки | Содержат PII/иногда HEALTH; ограничить распространение | Классификация/тегирование, DLP для e-mail/файлов, Encrypt-at-Rest |
| Реестры лаборатории | Содержат PII/HEALTH; внешняя передача | API-контракты с минимизацией, mTLS, подпись, журнал интеграций |
| Вложения почты | Неавторизованное распространение чувствительных данных | DLP/политики транспорта, шифрование вложений (S/MIME), запрет внешних доменов для HEALTH/PII |
| Метаданные/бэкапы | Скрытые атрибуты/возможность восстановления | Шифрование бэкапов, контроль доступа, политика сроков хранения |
| ТМЦ (накладные/серийники) | Возможна деанонимизация пациента | Разделение доменов, отсутствие PII, Encrypt-at-Rest |
