# Матрица защиты данных (At Rest / In Transit)

| Данные | В чём необходимость защиты | Инструменты защиты |
|---|---|---|
| PII пациента (ФИО, ДР, контакты) | Риск утечки ПДн, соответствие закону; доступ строго по ролям/атрибутам | Encrypt‑at‑Rest (KMS/Vault), TLS/mTLS, RBAC/ABAC, маскирование UI, DLP |
| HEALTH (медзаключения, результаты анализов) | Спецкатегория; конфиденциальность и аудит доступа | Шифрование объектов (Secure Storage+KMS), версии+аудит, псевдонимизация/обезличивание, mTLS к интеграциям |
| Финансы (чеки, проводки, договоры) | Предотвратить подмену/мошенничество | Подпись/хэш целостности, Encrypt‑at‑Rest, раздельные роли, защищённые каналы к 1С |
| Журналы/операционные списки | Содержат PII/иногда HEALTH | Классификация/тегирование, DLP, Encrypt‑at‑Rest |
| Реестры лаборатории | Передача наружу, PII/HEALTH | API‑контракты (минимизация), mTLS, подпись, журнал интеграций |
| Почтовые вложения | Неконтролируемое распространение | DLP/Transport Rules, S/MIME/шифр. вложений, запрет внешних доменов |
| Метаданные/бэкапы | Утечки скрытых атрибутов, восстановление | Шифрование бэкапов, доступ по ролям, policy сроков хранения |
| ТМЦ (накладные/серийники) | Возможна деанонимизация пациента | Разделение доменов, отсутствие PII, Encrypt‑at‑Rest |
