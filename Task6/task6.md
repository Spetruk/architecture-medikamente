# Слои данных
| Слои           | Назначение                                                 | Тип данных                                  | Уровень доступа                                     | Хранение                     |
| -------------- | ---------------------------------------------------------- | ------------------------------------------- | --------------------------------------------------- | ---------------------------- |
| Сырой          | Необработанные данные напрямую из источников               | PII, PHI, сканы, Excel, результаты анализов | Только классификатор, резервное восстановление      | S3 / MinIO (шифрованный)     |
| Чувствительный | Конфиденциальные данные до анонимизации                    | PII, PHI, паспорта, диагнозы                | Медицинские специалисты, администраторы (RBAC/ABAC) | PostgreSQL (TDE), S3 + Vault |
| Доверенный     | Обработанные анонимизированные и/или агрегированные данные | Обезличенные данные для анализа             | Аналитики, BI, ML, бухгалтерия                      | ClickHouse                   |
| Карантин       | Подозрительные или неоднозначные данные                    | Неопределённые, потенциально опасные        | Только служба безопасности                          | S3/DLP/Alerting              |

# Метрики 
Точность - % от правильно классифицированных PII/PHI среди всех помеченных (Минимизировать ложные срабатывания)
Полнота - % от найденных PII/PHI от общего числа реальных (Не пропустить конфиденциальные данные)
F1Score - Гармоническое среднее 'Точности' и 'Полноты' (Баланс между точностью и полнотой)
Скорость обработки - Кол-во строк/секунду (Способность к масштабируемости)
Количество инцидентов - Число алертов от DLP и аудита (Снижение рисков утечки)
Доля % данных, не поддающихся классификации (Выявить необходимость улучшения движка-классификации)

# Расширяемость
## Горизонтальное масштабирование
Контейнеризация -  Kubernetes управляет нагрузкой, auto-scaling по CPU/Memory
REST Full сервисы (без хранения состояний) - чтобы сервисы могли масштабироваться независимо
Внедрение шины данных (Kafka/Flink) - для надёжного и масштабируемого роста (но это для оооочень больших данных)
## Рост данных
ClickHouse — высокая производительность при аналитике
RBAC/ABAC — добавить политики доступа к данным для разных потребителей
Создание дополнительных витрин данных
